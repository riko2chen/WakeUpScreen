# 4.3.0 口袋模式兼容性排查与修复

对比基线：`v4.2.0`（`d377e5f`）与 `v4.3.0`（`340cbe5`）。口袋模式的主要改动来自 `fa3f7e6`（`fix: harden pocket and media notification filtering`）。本修复基于 4.3.0，发布版本 `4.3.1 / 43100`，分支 `agent/pocket-mode-compatibility`。

## 前后差异

| 项目 | 4.2.0 | 4.3.0 | 本次修复 |
| --- | --- | --- | --- |
| 遮挡阈值 | 传感器回调以 `distance == 0f` 判断近；离开零值后更新远状态 | 所有 `distance < maximumRange` 都判近 | 默认使用零值阈值；用户可打开试用开关采用最大量程判断 |
| 首次回调前 | 持久化值缺失时默认为远，但也可能读到上次进程残留的近状态 | 内存 `UNKNOWN`，默认拦截 | 内存 `UNKNOWN`，默认放行 |
| 无效距离或最大量程 | 没有显式校验 | 转成 `UNKNOWN`，拦截 | 无效距离两种策略均放行；无效量程在新版策略中放行，旧策略不依赖量程 |
| 无传感器／注册失败 | 没有区分注册成功与否 | `UNAVAILABLE`，放行；只有成功才标记已注册 | 保留 |
| 运行时状态 | 保存到设置，`Float.toInt()` 后用 `statueOfProximity == 0` 拦截 | 内存枚举状态，不信任持久化旧读数 | 保留内存状态，不恢复旧读数键的使用 |
| 重复注册 | 注销后重新注册，复用同一个回调对象 | 已注册直接返回；新会话新建回调，防止重复读数抑制使状态停在 `UNKNOWN` | 保留 |
| 服务重连和销毁 | 未统一在这些路径同步姿态传感器 | 创建及重连时按设置同步，销毁时注销 | 保留 |

旧代码还存在一个细节：从零距离切换到 `0 < distance < 1` 后，将正小数转成整数会得到 0，而后续正数回调又可能不更新状态。这会错误地继续拦截。修复恢复旧版的零值判断规则，但直接比较浮点数，不恢复该整数截断问题或持久化传感器状态。

## 为什么会出现旧版能亮、新版不能亮

1. **首次读数不返回时无限拦截。** 4.3.0 注册成功后先设置 `UNKNOWN`，没有超时或放行路径；只有收到有效读数后才能脱离未知状态。若问题设备的回调延迟、缺失或一直给出无效值，口袋模式就会持续拦截通知和重复提醒。这里注册成功只能证明监听器已注册，不能证明已经收到有效数据。
2. **非零距离被扩大为遮挡。** 例如距离 1、最大量程 5：4.2.0 的零值阈值允许亮屏，4.3.0 会判断为近并拦截。远状态不等于最大量程的设备，或者连续输出距离的设备，更容易受到影响。
3. **错误原因可能被日志掩盖。** 未知状态和实际近状态均使用 `pocket_mode` 阻断原因，用户看到的描述却是“检测到设备在口袋中”，无法区别未读到数据与确认遮挡。本次未知状态放行后，不会再以该原因误报阻断。

Android [位置传感器文档](https://developer.android.com/develop/sensors-and-location/sensors/sensors_position#java_2) 说明，部分接近传感器提供二值状态，远状态通常为最大量程、近状态为更小值；另一些提供厘米距离。因此最大量程策略有适用场景，但不能将缺少数据当作确定遮挡，也不适合未经选择就替代所有设备原有行为。

上述是代码层面的确定行为和回归触发条件。没有问题设备型号、实际读数及现场日志，不能断言某一厂商设备具体属于哪一种原因。这里的“读数”指接近传感器的距离或二值状态；本链路未使用角度，独立的“屏幕朝下静默”功能保持原样。

## 保留的修复与设置行为

- 不回退 `ScApplication` 的存储初始化／迁移和主题处理，也不回退 4.3.0 的 Activity 窗口兼容修复。4.2.0 → 4.3.0 间，`ScApplication` 本身没有口袋模式改动，高级设置 Activity 的口袋开关注册代码也未改变；真正的注册可靠性修复位于 `ProximitySensorState` 和通知服务。
- `ProximitySensorState` 继续从 `context.applicationContext` 获取 `SensorManager`，避免保存 Activity context；继续检查注册结果、使用内存状态、避免重复注册，并在新会话重建回调。
- 高级设置的口袋模式开关开启时，下方显示“尝试新版口袋检测”。新选项默认关闭，现有安装升级后使用零值策略；不会更改原有口袋模式总开关。
- 试用开启后，仅有效且 `distance < maximumRange` 的读数拦截。未收到读数、空回调、NaN、无穷、负距离、无传感器或注册失败均放行；新版的最大量程无效时也放行。
- 每个回调同时保存两种解释，切换试用选项立即重新选择判断，无需重新注册或等待下一次数据。正数从远变近或从近变远，即使在另一种策略下分类未变，也会更新。
- 通知决定、重复提醒和判断链预览共用相同条件。开关持久化并加入备份目录和设置搜索；旧备份缺少新字段时沿用当前选项，默认不会启用试用。
- 试用策略仍比零值策略覆盖更多近距离读数，默认关闭；用户遇到误判可以关闭试用选项恢复零值策略。

## 验证

- 全部 162 项 JVM 单元测试通过，无失败、错误或跳过。其中 12 项口袋模式测试覆盖零值及正小数阈值、未知和无效状态放行、试用立即切换、真实条件／预览入口、旧运行时值隔离，以及偏好备份往返。
- `:app:assembleDebug` 和 `:app:assembleDebugAndroidTest` 构建成功，生成可安装的调试 APK。
- `:app:lintDebug` 成功，无错误；报告包含 138 条 Warning 和 1 条 Hint，新口袋设置资源没有新增翻译警告。新增设备测试后再次执行 Lint 成功。
- Android 15 / API 35 模拟器的两项新增设备测试通过，无跳过：使用实际 Android `SensorEvent` 和传感器量程验证回调；使用实际 SensorManager 验证重复注册复用监听器、注销后新建监听器、首次回调前保持未知并放行。
- 设置页面冒烟确认试用选项在口袋模式下显示，默认关闭，点击后打开并写入偏好，强制停止／冷启动后偏好仍保留。
- 与 `v4.3.0` 比较，`ScApplication`、`ScBaseActivity`、`MainActivity`、`ScNotificationListenerService` 均无差异，原有初始化、窗口和服务生命周期修复保持完整。
- 4.3.1 版本递增后重新执行全部 162 项单元测试、Debug / Release 构建、Lint 和 `verifyReleaseOptimization`，全部成功。最终 APK 的 versionName / versionCode 已核对为 `4.3.1 / 43100`；Release AAB 已验证 R8、内嵌 mapping 和资源压缩。
- 验证日志和截图保存于 `app/build/reports/pocket-mode-compatibility/`。版本号已递增为 `4.3.1 / 43100`；未发布。

没有在报告问题的厂商真机上执行测试；模拟器结果不能替代实际设备亮屏验证。需要在受影响的设备上额外确认息屏接收通知、遮挡后移开、重启通知监听服务及切换两种策略的行为。
