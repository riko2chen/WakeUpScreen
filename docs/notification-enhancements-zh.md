# 通知与重复提醒增强

本轮从 `d377e5f` 建立独立功能分支。用户原工作目录的 `dev/4.3.0` 未提交修改不属于这些分支。

## 任务与分支

| 功能 | 分支 | 验收重点 |
| --- | --- | --- |
| 重复提醒应用选择 | `codex/reminder-app-selection` | 默认沿用首次亮屏规则；子集不能绕过原过滤；空选择不提醒 |
| 重复提醒可靠性 | `codex/reminder-reliability` | 更新不无限推迟；逐条筛选；共享周期；次数上限和清除行为 |
| 独立亮屏时长 | `codex/reminder-duration` | 默认继承；自定义只影响提醒；授权缺失有明确提示 |
| 自定义间隔 | `codex/reminder-custom-interval` | 快捷选项及自定义；无效输入不保存；立即按新间隔调度 |
| 提醒振动 | `codex/reminder-vibration` | 默认关闭；仅提醒成功通过规则后触发；尊重勿扰和静音 |
| 指定蓝牙设备条件 | `codex/bluetooth-wake-condition` | 默认关闭；多选设备任一连接才允许；覆盖首次亮屏和提醒；权限/断连状态明确 |

集成与组合验证分支：`codex/notification-enhancements`。每项功能由单独 Astra subagent 实现。

不包含切歌亮屏、提示音、双击唤醒、音量键唤醒或歌名悬浮窗。

## 组合行为

- A/B/C 都可首次亮屏，提醒子集仅选 A 时，B/C 不建立或维持提醒批次。
- 一个批次包含多条通知时，共享一次提醒，不产生每条通知独立唤醒。
- 静默通知不会遮蔽同批次其他符合条件的通知。
- 蓝牙条件开启且指定设备未连接时，首次亮屏与提醒均被阻止，振动也不应触发。
- 重复提醒独立时长不能改变首次通知的亮屏时长。
- 新增偏好可持久化、导入导出，已有用户默认行为保留。
- 自定义提醒间隔是期望间隔，系统省电机制可能延迟实际触发。
- 自定义间隔范围为 5–1440 分钟；独立提醒亮屏时长为 5–30 秒，也可沿用首次通知设置。
- Android 9 及以上的独立亮屏时长需要无障碍锁屏服务；未授权或服务未连接时按系统超时熄屏，界面提示限制。

## 设备验证边界

- 蓝牙条件启用后，多选设备中任意一台已配对且已连接即可通过；权限缺失、蓝牙关闭、未选设备或连接状态未知时阻止亮屏。
- 首次连接快照最多等待 1.5 秒，期间到达的通知会重新检查并合并为至多一次亮屏。提醒的启动重查仍使用系统非精确闹钟，实际执行可能受省电机制延迟。
- 启动时可查询常见音频和 GATT 连接；其他类型已存在的连接可能需要在监听期间重新连接。详见 [蓝牙设备验证清单](bluetooth-wake-condition.md)。
- 模拟器可以验证策略、权限缺失和界面，无法代替真实耳机/车机的连接测试、振动触感和不同厂商的熄屏行为测试。
