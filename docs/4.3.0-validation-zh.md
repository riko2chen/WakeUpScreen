# 4.3.0 修复与验证记录

分支：`dev/4.3.0`。应用版本：`43000 / 4.3.0`。

## 已实施修改

- 普通 Activity 统一调用 AndroidX `enableEdgeToEdge()`，移除自有代码和主题中的 `statusBarColor` / `navigationBarColor` 设置。页面背景负责系统栏区域颜色，单独管理图标明暗。
- Compose 页面使用对应方向的 `safeDrawing` 安全区域，覆盖系统栏、屏幕挖孔、窗口标题栏和键盘。主页面底部导航独立处理左右及底部空间，避免与 Compose 重复处理。
- 应用筛选页同时处理左右挖孔、顶部系统栏和底部键盘，原有 padding 在每次更新时只叠加一次；深色渐变标题固定使用浅色状态栏图标。
- 黑屏和夜间微光窗口使用兼容无边框布局及 `WindowInsetsControllerCompat.hide(systemBars())`，不再靠系统栏颜色制造全黑效果。
- 应用列表数据不再持有 Drawable。条目绑定时异步加载实际显示尺寸的图标，最多同时加载 2 个，位图缓存以字节计上限 2 MiB。条目回收取消请求，页面销毁取消所有任务并清空缓存；不手动 recycle 仍可能被 View 使用的位图。
- 页面销毁与图标加载并发时，关闭后的请求以协程取消结束，不向应用抛出普通异常。
- 自适应图标通过 Drawable 绘制，支持应用卸载或图标资源异常时的默认图标回退。应用介绍页和设置页共用按尺寸异步加载组件，修复将 adaptive-icon XML 当作位图解码的问题。
- 列表空搜索结果会清空旧条目，重新筛选保留当前选择，避免重新套用初始保存状态。
- 移除唯一用途已被替代的 Glide 与 kapt。Core 更新到 1.16.0、Activity 更新到 1.10.1、Material 更新到 1.13.0。
- 保留 release 的 R8 和资源压缩，并添加 `:app:verifyReleaseOptimization`。该任务验证 release 开关、最终合并规则及 AAB 内嵌 R8 mapping；发布工作流必须通过此检查。
- 同步应用内和文档中的多语言 4.3.0 更新说明。

## 验证

- 107 项单元测试通过，无失败、错误或跳过。
- 最终 `assembleDebug`、`assembleDebugAndroidTest`、`assembleRelease`、`verifyReleaseOptimization`、`lintDebug` 构建成功；最终构建耗时 5 分 59 秒。Lint 无错误，仍有警告；发布关键检查通过。
- Android 15 / API 35 模拟器：竖屏、浅色、手势导航配置下，最初的 8 项新增设备回归通过。
- 最终代码在横屏、深色、摄像头挖孔、三键导航的组合配置下，9 项新增回归和 2 项通知排名测试全部通过，共 11 项。还关闭了 Android 15 的 `ENFORCE_EDGE_TO_EDGE` 兼容性开关，验证应用主动启用无边框；这不等于实际测试过 Android 14 或更早系统。
- 新增回归覆盖：应用介绍页、自适应图标、丢失应用图标回退、缓存按字节淘汰、不同显示尺寸、关闭后取消请求、左右挖孔和键盘留白、重复 insets 分发、空搜索与选择状态、夜间微光隐藏系统栏。
- 既有通知测试在整套执行中出现时序失败。排名用例现会等待系统异步提供排名，保留原始重要性断言，最终两项均通过；要求移除通知后不到 1 秒记录结果的用例未放宽断言，单独复测通过。全套执行中的时序波动仍需关注，不能把本次结果描述为整套设备测试始终无失败。
- 组合配置首次启动测试时被系统以启动超时终止，未进入用例；相同配置重跑的 11 项测试通过。
- 使用本地调试密钥签名的最终混淆 release APK 完成人工冒烟：主页、设置页、展开的应用介绍图标、白名单列表及条目图标均正常显示，系统栏与内容留白正常。恢复竖屏、浅色和手势导航后再次冷启动返回 `Status: ok`。截图与启动记录保存在下述日志目录。
- 冒烟期间模拟器的 Pixel Launcher 和 System UI 出现过无响应，恢复系统组件后继续验证通过。本次启动耗时受测试环境影响，不据此给出启动性能改善结论。

测试日志位于 `app/build/reports/4.3.0/`，包括最终构建、组合配置测试、原有通知用例的整套与隔离执行记录。

## 验证边界

Play Console 的线上提示和实际上传包无法从本地替代核验。兼容库可能保留旧 Android 必需的 API 调用，不能承诺仅凭本地无弃用调用就让平台提示消失。

缓存上限与按需加载通过代码和回归测试验证；不将 APK / AAB 体积变化当作真实设备峰值内存下降比例。不同 Android 版本和厂商设备仍需发布前回归。
