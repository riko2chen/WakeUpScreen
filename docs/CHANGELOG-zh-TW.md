# 更新日誌

WakeUpScreen 各版本的主要變更紀錄。

---

## [4.0.0]

### 新增
- 首頁顯示上次成功喚醒於多久之前（剛剛 / 分鐘 / 小時 / 天），資料直接來自通知日誌，點擊可開啟日誌
- 睡眠時段支援依星期幾生效，提供「每天 / 平日 / 週末」快速預設。跨午夜的時段歸屬於開始的那一晚：週五 23:00 - 07:00 依然涵蓋週六早晨。既有時段維持每天生效
- 新規則「低電量靜默」：電量低於所選閾值（5-50%）且未充電時，通知不再亮螢幕；充電中始終放行
- 新規則「面朝下靜默」：手機螢幕朝下倒扣放置時通知不亮螢幕。由加速度計判斷，與口袋模式使用距離感測器是同一套機制
- 「夜間紅光」：睡眠時段內可選擇短暫顯示微弱紅光（最低亮度、黑色背景），不再完全黑屏，適合值班、育兒等需要夜間待命的情境。選紅色是因為它對暗適應視覺的干擾最小；在日誌中以獨立狀態記錄
- 注意力統計：完全在本機進行，僅基於兩個事件——螢幕被喚醒、以及半分鐘內是否解鎖——統計最近 30 天哪些應用程式頻繁亮螢幕卻從不被理會，並對最嚴重的應用程式提供一鍵加入黑名單。不讀取任何通知內容
- 設定支援匯出為 JSON 檔案、在其他裝置匯入，透過系統檔案選擇器完成，不新增權限。檔案格式帶版本號：舊版本會忽略它不認識的新設定項，來自較新格式的檔案會被明確拒絕並提示，而不是匯入一半
- 應用程式內更新日誌：更新後首次開啟會彈出簡短的更新摘要，跨版本更新時逐版本列出，不只顯示最新一版。也可隨時從「設定 → 關於 → 更新日誌」查看；更新新增的設定項會帶一個小圓點提示，點開後消失

### 變更
- 兩條新規則與其他規則一樣，出現在通知判斷過程圖示和通知日誌中
- 精確亮螢幕時長到點熄螢幕前會先確認鍵盤鎖還在：如果你在視窗期間已經解鎖（或螢幕鎖定方式設為「無」），視窗直接結束、不再鎖定螢幕。此前在解鎖廣播偶發遺失的機型上，可能在使用中被鎖定螢幕
- 精確亮螢幕時長的最短檔從 3 秒改為 5 秒。上面的鍵盤鎖檢查需要避開部分機型喚醒初期的誤報視窗；已儲存的更短設定會自動提升到 5 秒
- 自訂亮螢幕時長：未開啟無障礙權限時改為醒目的紅色警示；開關開啟但未授權就離開頁面時，會彈窗提醒，可選擇前往開啟或仍然返回

### 說明
- 未新增任何權限
- 本版本儲存的睡眠時段若未限制星期，3.2.0 仍可讀取；限制了星期的時段在舊版本中會被捨棄而不是誤讀

## [3.2.0]

### 新增
- 睡眠模式支援多個時段。可以分別新增、刪除，例如夜間一段、午休一段
- 睡眠時段精確到分鐘，不再限制為整點
- 睡眠時間頁新增 24 小時圓環，睡眠時段在環上以灰色標示，並標出目前時刻。環上標有 0、6、12、18 四個刻度
- 新增時段時會檢查與既有時段是否重疊，重疊會指出具體是哪一段並阻止新增

### 變更
- 配色依 Material 3 重做。顏色不再逐一手寫，而是由品牌色產生整套色階，淺色和深色分別取各自規定的檔位，因此兩套配色不會再出現一邊調好、另一邊錯位的情況
- 頂部列去掉漸層，改為純色。狀態列顏色與圖示明暗跟隨目前頁面：首頁頂部仍是深色漸層，其餘頁面跟隨淺色或深色主題
- 卡片、搜尋框、頂部列之間改用 Material 3 的表面層級區分，深色下不再和背景糊成一片
- 24 小時圓環標出全部 0 到 23 時，此前只標 0、6、12、18，例如 02:00 - 04:00 到 03:59 為止。兩個時段因此可以首尾相接，一段的結束時間正好是下一段的開始時間
- 原有的單一睡眠時段會在升級後自動轉換為一個時段，行為不變
- 「持續通知最佳化」改名為「攔截持續通知」，「嚴格的持續通知過濾」改名為「攔截常駐通知」。兩個開關的標題後增加問號按鈕，點開說明各自攔什麼、差異在哪
- 設定頁重新分組為「一般」「進階」「診斷」「關於」。一般放語言和新增的深色模式；進階放通知判斷過程和亮屏規則頁；診斷放亮屏測試和日誌入口
- 新增深色模式，可選跟隨系統、淺色、深色三種。預設跟隨系統，升級後外觀不變
- 亮螢幕時長和應用程式過濾（模式、白名單、黑名單）從設定首頁移入亮屏規則頁，該頁現在集中了所有決定亮不亮螢幕的設定
- 部分條目改名，讓名字直接說明用途：「進階設定」改為「亮屏規則」，「攔截鏈路」改為「通知判斷過程」，「功能測試」改為「亮屏測試」，「目前模式」改為「過濾模式」。僅改顯示名稱，所有設定項的值保持不變

### 修復
- 修復「嚴格的持續通知過濾」（設定 → 亮屏規則）寫錯設定項的問題：開關這一項實際改動的是普通的「常駐通知偵測」，而嚴格過濾本身從未被儲存 —— 每次重新進入頁面都會變回開啟狀態。現在兩個開關互相獨立，也能正常儲存

### 說明
- 修復前嚴格過濾實際上始終生效，修復後預設仍為開啟，升級不會改變通知過濾行為
- 如果曾經撥動過嚴格過濾開關，普通的「常駐通知偵測」可能已被一併改動，建議到「設定 → 亮屏規則」確認兩個開關的狀態

## [3.1.1]

### 變更
- 目標 API 升級到 Android 16（API 36）。已在 Android 16 系統映像上驗證：精確亮螢幕時長、無障礙鎖定螢幕動作、以及無需權限的後備熄螢幕方式，行為與之前完全一致
- 二級頁面的返回動畫改為 Android 的預測式返回動畫，不再使用應用程式自帶的滑動轉場。這是相容 Android 16 後由系統接管的效果，僅影響觀感，返回邏輯本身沒有變化

### 說明
- 未新增任何權限，功能沒有變化
- 已在使用 16 KB 記憶體分頁的裝置映像上驗證可正常執行

---

## [3.1.0]

### 新功能
- 新增「重複提醒」（設定 → 進階設定）：只要通知還沒處理，螢幕每隔 5～60 分鐘再次亮起，通知被清除後立即停止。間隔與同一批未讀通知的最多提醒次數均可調整；睡眠模式、勿擾模式、口袋模式、僅充電時亮屏、應用程式篩選的優先順序仍然更高，常駐通知不計入未讀
- 提醒亮螢幕會記入通知日誌；功能測試可立即執行一次提醒，無需等待整個間隔
- 新增「自訂亮螢幕時長」（設定 → 自訂亮螢幕時長）：螢幕保持點亮 3、5、10、15 或 30 秒後主動熄滅，不再交還給系統的「螢幕逾時」。熄螢幕透過系統內建的「鎖定螢幕」動作完成，需要一個可選的無障礙服務，該服務不讀取任何螢幕內容

### 變更
- 自訂亮螢幕時長預設關閉，關閉時不做任何事，已安裝用戶的行為與之前完全一致 —— 舊實作在取得喚醒鎖後立即釋放，設定的秒數本就從未生效

### 說明
- 未新增任何權限。提醒使用非精確鬧鐘，Doze 休眠可能讓某次提醒晚幾分鐘抵達
- 計時期間若解鎖裝置或螢幕提前熄滅，計時立即取消；通話過程中不會強制熄螢幕

## [3.0.6]

### 變更
- 移除 `FOREGROUND_SERVICE_SPECIAL_USE` 權限。點亮螢幕依賴通知監聽服務，該服務由系統自動綁定保持存活，核心功能本就不需要這個特殊用途的前景服務。
- 移除可選的「常駐通知（保持服務存活）」設定，它是唯一用到該權限的功能。在積極管理背景程式的機型上，請改為將本應用程式加入電池最佳化白名單以確保可靠性。

## [3.0.4]

### 修復
- 修復 release 版本通知日誌始終顯示「未知原因」的問題 —— 攔截原因改用穩定識別碼記錄（不再依賴會被混淆的類別名稱），現在能正確顯示真實原因（勿擾、充電、睡眠模式等）
- 常駐通知開關切換後立即生效，無需重新啟動應用程式或服務

### 最佳化
- 日誌中無法識別的攔截原因現在原樣顯示，而不再統一歸為「未知原因」，便於排解問題時不遺失資訊
